3. Four-Layer Security Architecture

The security system mirrors the nibble architecture with four layers:

  ┌──────────────────────────────────────────────┐
  │  LAYER 4 (HEAVEN): KEY CEREMONY             │  1111 ____
  │  Key Generation, S-Box, Diffusion            │
  ├──────────────────────────────────────────────┤
  │  LAYER 3 (HEAVEN): ENCRYPTION               │  1010 ____
  │  Stream Cipher + Heaven/Earth Transposition  │
  ├──────────────────────────────────────────────┤
  │  LAYER 2 (EARTH): INTEGRITY                 │  ____ 1110
  │  Checksums, Chain Proofs, Verification       │
  ├──────────────────────────────────────────────┤
  │  LAYER 1 (EARTH): IDENTITY & ACCESS          │  ____ 1011
  │  6-Tier Hierarchy, Challenge-Response        │
  └──────────────────────────────────────────────┘

Layer 4 (Key Ceremony) derives 256-bit keys from passphrases using a substitution box (S-Box) seeded by the Heaven on Earth constants. 12 diffusion rounds spread each bit's influence. The final whitening phase swaps Heaven and Earth nibbles before a last substitution.

Layer 3 (Encryption) implements a stream cipher. The keystream is generated through S-Box feedback, and plaintext is XORed with keystream bytes. On alternating bytes, a Heaven/Earth nibble transposition adds structural non-linearity.

Layer 2 (Integrity) provides checksums, chain-linked proofs, and authentication tags. The tag computation uses a keyed hash with cross-lane mixing. All comparisons are constant-time to prevent timing attacks.

Layer 1 (Identity) manages a six-tier access hierarchy, identity creation with denial screening, and challenge-response authentication.

8. Cryptographic Primitives

8.1 S-Box Construction

The substitution box is derived from the Heaven on Earth constants. For each byte value 0–255, the S-Box maps it to a substituted value using bit rotation combined with XOR against the cultural seed constants. This provides non-linearity essential for cryptographic strength. 

  for i in 0..255:
    seed = HEAVEN_ON_EARTH[i % 12]
    rotated = (i << 3) | (i >>> 5)   // bit rotation
    SBOX[i] = rotated XOR seed

8.2 Key Generation (The Ceremony)

Key generation proceeds in three phases:

  1. Seeding: Each passphrase character is XORed with a rotating Heaven on Earth constant and folded into a 32-byte array.
  2. Diffusion: 12 rounds of S-Box substitution with neighbor mixing spread each bit's influence across all 32 bytes.
  3. Whitening: Heaven and Earth nibbles are swapped, then a final S-Box pass produces the key.

8.3 Stream Cipher

Encryption uses a 32-byte state initialized from key XOR IV. For each byte, the state advances through S-Box feedback, and the plaintext byte is XORed with the resulting keystream byte. On odd-indexed bytes, a nibble swap (Heaven/Earth transposition) adds structural variation.

8.4 Authentication Tag

A 16-byte MAC is computed using a keyed hash with cross-lane mixing. Four final mixing rounds ensure diffusion. All tag comparisons use constant-time comparison to prevent timing side-channels.

9. Challenge-Response Authentication

To prove identity without revealing the key, the system issues a challenge containing a nonce and a randomly selected Heaven on Earth word. The prover computes a 16-byte proof by combining their key, the nonce, and the word value through the S-Box. The verifier recomputes the expected proof and performs a constant-time comparison. Challenges expire after 30 seconds. 

  Challenge:  { nonce, heavenWord, timestamp, expiresAt }
  Response:   proof[i] = SBOX[ key[i] XOR nonce[i] XOR HEAVEN_ON_EARTH[heavenWord] ]
  Verify:     constantTimeEqual(response.proof, expected.proof)

  SBOX[i] = ((i << 3) | (i >>> 5)) XOR seeds[i % 12]

  Inverse SBOX: for all i, INV_SBOX[SBOX[i]] = i
